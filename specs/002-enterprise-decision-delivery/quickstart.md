# Validation guide

Use the repository's Node/npm versions and lockfile. Start with `npm ci`, the full `npm run check`, and focused feature/release regressions; record actual command outcomes.

At `/sec/decision-center`, select every scenario, compare metadata/options, progress to review, acknowledge, try each outcome on separate runs, export, and reset. Switch scenario after review and language during progress; verify correct isolation/continuity. Inspect downloads for complete simulation/source/approval disclosures and no credentials/real data.

Inspect Arabic/English and dark/light at 360/390/430/768/1280px. Check keyboard focus, no horizontal overflow, and 44px primary controls. Observe that feature actions issue no mutating requests or provider calls.

Exercise isolated oversized/multibyte/never-completing body streams, preaborted dispatch, never-settling agents, parent abort, deadline, and late success/failure. Verify bounded caller completion and cleanup; do not mistake it for forced termination of noncooperative work.

For delivery, observe exact-head CI and PR eligibility, record merged SHA and known-good recovery target, deploy that SHA only, then verify deployed identity/routes/health. Test fail-closed eligibility and recovery logic offline before live release. Exercise live rollback only for a real failed/inconclusive authorized release; do not manufacture a Production incident for a demonstration.

Audit findings must cite their evidence level. Leave live RLS/auth/provider behavior unverified unless actual authorized measurements are available.
