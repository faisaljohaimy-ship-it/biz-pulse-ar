# Feature Specification: مسودات سير عمل معطلة من طلب مقيد

**Feature Branch**: `feature/sadeed-disabled-workflow-drafts-20261123`

**Created**: 2026-11-23

**Status**: استئناف ٢٠٢٦/١١/٢٤ — المعاينة وحفظ المسودة المعطلة منفذان في المصدر، مع اعتماد المالك المحدد وتطبيقه للصلاحيات. لم يُختبر حفظ/عزل صفوف الإنتاج؛ قبول US2 السلوكي ما زال مفتوحًا. التفاصيل في [متابعة التنفيذ](continuation-2026-11-24.md)؛ نطاق التقييم الأصلي أدناه تاريخي.

**Input**: شريحة محدودة من الميزة 11: تحويل طلب عربي أو إنجليزي ضمن قالب تشخيصي مسموح إلى مسودة محفوظة ومعطلة، بعد معاينة واختيار جهة صريح ومراجعة بشرية. لا تشغيل أو تنشيط أو إرسال خارجي. أُوقف تنفيذ الحفظ في هذه الدفعة لأن المسار المأذون لا يملك INSERT، تطبيقًا لتوجيه المالك بعدم تجاوز الصلاحيات، مع إبقاء العمل المستقل المسموح.

## User Scenarios & Testing _(mandatory)_

### User Story 1 — معاينة طلب مدعوم بحدود واضحة (Priority: P1)

يختار المستخدم جهة من عضوياته بنفسه، ويطلب مسودة تشخيص الأصول غير المتصلة بالعربية أو الإنجليزية. يرى المعلمات والحد العددي وحالة التعطيل قبل أي حفظ.

**Why this priority**: المعاينة تمنع تفسير طلب غير مدعوم على أنه إجراء جاهز، وتوضح الجهة المقصودة بدل اختيارها ضمنيًا.

**Independent acceptance**: مراجعة عقد الطلب والمخرجات وحدود الصلاحية. لا اختبارات أو تشغيل CI اختياري أو استدعاء بيانات أعمال في هذه الدفعة.

**Acceptance Scenarios**:

1. **Given** عضوية في جهة واحدة أو أكثر، **When** يفتح المستخدم النموذج، **Then** يبقى اختيار الجهة فارغًا حتى يختارها صراحة.
2. **Given** طلب تشخيص الأصول غير المتصلة المدعوم، **When** يعاين المستخدم الخطة، **Then** تظهر قراءة تشخيصية واحدة بحالة `offline` وحد صحيح بين 1 و50، بلا تنفيذ أو نتائج مختلقة.
3. **Given** الطلب «عند اقتراب انتهاء تصريح مرتبط بأصل حرج، جهز مهمة مراجعة للمسؤول»، **When** يطلب المستخدم المعاينة، **Then** يُرفض بوضوح بوصفه غير مدعوم، دون تحويله إلى قالب آخر أو ادعاء إنشاء مهمة.

### User Story 2 — حفظ مسودة معطلة وقراءة إقرارها (Priority: P1، محجوب حاليًا)

بعد مراجعة المعلمات والجهة، يحفظ المستخدم المسودة صراحة ويستلم إقرارًا من السجل المحفوظ نفسه. المراجعة هنا ليست اعتمادًا تشغيليًا أو إذن تنشيط.

**Why this priority**: النص الوصفي وحده لا يحقق طلب المالك بحفظ مسودة فعلية.

**Independent acceptance**: لا تُغلق هذه القصة قبل توافر مسار كتابة مأذون ونجاح قراءة إقرار السجل؛ قراءة الكود أو metadata لا تثبت الحفظ.

**Acceptance Scenarios**:

1. **Given** صلاحية كتابة فعلية وهوية وعضوية حاليتان، **When** يراجع المستخدم المعلمات ويحفظ، **Then** تُحفظ مسودة واحدة معطلة، بلا حدث تشغيل أو إرسال أو تنشيط.
2. **Given** محاولة حفظ سابقة لم تُعرف نتيجتها، **When** يُعاد الطلب بالمعرف نفسه، **Then** لا يُستبدل سجل موجود؛ لا يُقر إلا سجل مطابق للمالك والجهة والمعلمات وحالة التعطيل.
3. **Given** غياب امتياز الكتابة الفعلي كما هو حاليًا، **When** يُقيّم التسليم، **Then** يذكر التقرير أن الحفظ غير متاح، دون زر يوهم بتوافره أو تجاوز صلاحيات المستخدم.

### Edge Cases

طلب غير مسموح أو طويل، جهة غير مختارة أو عضوية مسحوبة، دور مشاهد، حد غير صحيح أو أكبر من50، معرف مكرر بمعلمات مختلفة، فشل حفظ أو قراءة إقرار، وتغير هوية المستخدم أثناء الطلب. لا يُفسر الخطأ على أنه عدم حدوث كتابة، ولا تُعاد المحاولة بمعرف جديد تلقائيًا.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: يقتصر التحويل على قالب قراءة تشخيص الأصول غير المتصلة، مع مطابقة حتمية عربية وإنجليزية وحد صحيح 1–50؛ لا نموذج لغوي أو إنفاق مزود.
- **FR-002**: تُعرض الجهة والمعلمات للمراجعة قبل الحفظ. لا اختيار تلقائي لأول عضوية أو للجهة الحالية.
- **FR-003**: يُعاد التحقق من هوية المستخدم وعضويته الحالية ودوره وصلاحيات الكتابة الفعلية عند الحفظ، دون توسيعها.
- **FR-004**: تبقى كل مسودة معطلة وغير مرتبطة بموضوع تشغيل؛ لا جدولة أو نشر حدث أو تشغيل أداة أو رسالة خارجية أو API تنشيط.
- **FR-005**: يثبت إقرار الحفظ سجلًا مطابقًا للطلب والمالك والجهة. إعادة المعرف نفسه لا تعدل سجلًا ولا تدعي منع التكرار عبر معرفات جديدة.
- **FR-006**: الطلبات المتعلقة بانتهاء التصاريح أو ربط الأصول الحرجة أو إنشاء مهمة مراجعة خارج هذا القالب تُرفض صراحة.
- **FR-007**: غياب امتياز INSERT الفعلي عائق تسليم، لا مبرر لمنح صلاحية أو تجاوز RLS أو استخدام عميل ذي امتياز أعلى. لا API أو زر حفظ ميت في هذه الدفعة.
- **FR-008**: لا اختبارات جديدة أو تشغيل اختبارات أو CI أو كتابة أعمال أو migrations أو تعديل رايات أو مزودين في نطاق هذا التقييم. تبقى البوابات الإلزامية القائمة محفوظة.

### Key Entities

- **طلب مقيد**: لغة مدعومة، جهة يختارها المستخدم، حد القراءة، وقالب تشخيص واحد.
- **مسودة معطلة**: هوية ومالك وجهة ومعلمات ثابتة وحالة غير نشطة، وليست موافقة أو إجراء منفذًا.
- **إقرار حفظ**: قراءة للسجل المطابق، مع بيان إعادة الطلب عند تطابق المعرف؛ ليس نتيجة تشخيص.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: يميز التسليم بين المعاينة والحفظ الفعلي والتنشيط، ويصرح بأن الحفظ محجوب حاليًا.
- **SC-002**: لا ينتج الطلب المدعوم إلا قالب قراءة واحدًا، ولا يُقبل الطلب غير المدعوم بتفسير بديل صامت.
- **SC-003**: لا تُنشأ صفوف أعمال أو صلاحيات أو رايات أو إجراءات تشغيلية أثناء هذا التقييم.
- **SC-004**: لا تُعلن الميزة 11 مكتملة حتى يتوافر حفظ مأذون وإقرار مطابق فعلي؛ هذه المواصفات وحدها لا تحققها.

## Assumptions

المسار الحالي وعضويات الجهات والمصادقة والمحرك القائمون مصادر إعادة الاستخدام. لم يُؤذن بتغيير SQL ACL أو RLS أو تفويض عميل يتجاوزهما. الدليل التفصيلي والعقد المؤجل في [plan.md](plan.md)، والمهام المحجوبة في [tasks.md](tasks.md).
