# OMEGA validation guide

Use the existing npm lockfile and Node/npm versions. Run focused model/UI/report checks, then the full `npm run check` and required browser/CD regression checks; record actual outputs instead of predicting success.

At `/sec/decision-center`, inspect each scenario's world projection and evidence, dependency trace, rule hypothesis and missing facts. Change each of the five controls separately; compare baseline and variant while checking that the baseline/event severity remain unchanged. After local review/export, change an assumption and confirm controlled UI state invalidates stale acknowledgement/review/export eligibility. Do not describe this as a serializer-authenticated review history.

Switch scenario/reset and confirm fresh defaults. Switch locale and confirm assumptions/state remain meaningful with RTL/LTR. Complete review and inspect the downloaded HTML for the exact scenario/inputs, canonical explanations and simulation/no-authority limits. Confirm no network/tool/DB/provider/seed action occurs.

Check 360/390/430/768/1280px, both languages/themes, keyboard, 44px primary targets, no overflow, reduced motion, nonempty evidence and rejection paths. Test malformed/nonfinite/out-of-range assumptions, unknown references/scenarios, cycles/depth bounds and report altered event/severity/evidence, foreign scenario, extra result fields or malformed inputs. The serializer rebuilds canonical content but receives caller-supplied review state; it is not a signature, actor authenticator or durable/tamperproof audit.

Read the [15-capability roadmap](../../docs/strategy/OMEGA_CAPABILITY_ROADMAP_2026-11-22.md), [Innovation Gap Matrix](../../docs/audit/OMEGA_INNOVATION_GAP_MATRIX_2026-11-22.md), [quality evidence](../../docs/audit/OMEGA_QUALITY_EVIDENCE_2026-11-22.md), and [3–5 minute demonstration](../../docs/operations/OMEGA_EXECUTIVE_DEMO_AR.md). Their maturity/source limits are acceptance criteria, not marketing footnotes.

Establish/record a new finite task cycle before first push; count all artifact states and preserve two emergency deployments. Follow existing exact-head CI/PR/main-CI/staged verification/promotion/90-second dual-domain verification, reporting the actual release or blocker.
