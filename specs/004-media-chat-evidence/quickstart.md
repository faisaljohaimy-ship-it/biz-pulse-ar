# Validation Guide: وسائط سديد والتحقق من التسليم

## المتطلبات

الفرع `feature/sadeed-media-chat-evidence-20261123`، وعقد [الوسائط والقبول](contracts/media-and-acceptance.md)، والأصول الأصلية. يلزم حساب/جلسة اختبار قائم ومصرح به، و iPhone Safari فعلي للقبول. لا توضع بيانات الاعتماد في الملف أو سجل الأوامر أو PR؛ يتولى root الطريقة الآمنة المتاحة. غيابهما عائق، لا تخطٍّ ناجح.

## الفحص المحلي

تشغل الأوامر عند تكامل الكود لا بالتوازي مع بناء ثقيل آخر على البيئة المحدودة:

```sh
npm ci
npm run typecheck
npm run lint
npm test -- --maxWorkers=1
npm run build
npm run check:performance
npm run check:contrast
npm run check:secrets
npm run check:audit
```

هذه خطوات تشغيل مقترحة؛ نتائجها الفعلية تُسجل في [سجل الأدلة](../../docs/audit/MEDIA_CHAT_EVIDENCE_2026-11-23.md). استخدم ملفات اختبارات الوسائط الحالية/الجديدة التي يثبتها مالك الكود في tasks؛ لا تُعدّل حدود الأداء كي يمر الفحص.

## رحلة قبول A

1. افتح `/` بزيارة جديدة، ثم تنقل وعد؛ تأكد من الصورة الكاملة ومطابقتها وصفر طلبات بيانات فيديو قبل تشغيل المعرض صراحة، بما يشمل الافتتاح والخلفية. افحص الخطأ والحركة/الشبكة والوضعين.
2. انتقل إلى قسم `HomeTwinSection` القائم أسفل الرئيسية وشغّل كل فيلم بنفسه. تحقق من المصدر والمدة والسرعة والإفصاح، ثم بدّل وغادر الصفحة وأعدها؛ تأكد من توقف السابق والتنظيف.
3. كرر العرض بالعربية والإنجليزية والوضعين عند 360/390/430/768/1280 بكسل. تحقق من 44×44 بكسل، لوحة المفاتيح وعدم السكرول الأفقي.
4. نفّذ تسجيل الدخول الفعلي بطريقة مصرح بها؛ أثبت الجلسة والوصول المطلوب. سجل عرض النموذج منفصلًا. لا ترسل نموذجًا ببيانات وهمية ولا تحفظ أسرارًا.
5. نفّذ على iPhone Safari حقيقي، وسجل طراز الجهاز/الإصدار والنتيجة؛ وثق WebKit منفصلًا إن استُخدم. إن تعذر الجهاز، سجل BLOCKED.
6. راجع الطلبات والأخطاء؛ لا عمليات أمنية ولا إرسال دردشة/صوت/موصل مدفوع لمجرد اختبار الوسائط.

## المراحل B–D

راجع صفوف القدرات الاثنتي عشرة ومصادرها وحدودها. أي إصلاح مختار يحتاج مُعيدًا واختبارًا حقيقيًا يحمَر عند العطل ويثبت الحماية المجاورة. افصل الأداء المحلي المزيّف من زمن مزود حي، وأهداف السرعة من قياساتها. لا تجرب تكاملًا حيًا أو كتابة دون نطاق مصرح مناسب.

## التحقق البعيد

راجع PR453 و main الحالي، ثم تصريح الحارس والدورة الجديدة قبل الدفع. تحقق من exact-head CI ثم merged-main CI، والأثر المرحلي نفسه قبل الترقية وبعدها على النطاقين خلال 90 ثانية. استخدم `/api/public/live` للهوية؛ فحوص health قد تكتب عدادات، والدردشة قد تنفق. دوّن الأثر المعروف السليم والتعافي الفعلي إن لزم. تبقى الشروط BLOCKED ظاهرة حتى بعد نشر تقني ناجح.
