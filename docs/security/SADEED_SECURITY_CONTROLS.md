# SADEED — Security controls register (2026-10-17)

Each control names where it is enforced, the test that proves it, and its verification state. "Verified" means a test ran in this release's gate chain (local and CI run #726 and later) or the behaviour was measured; "unverified" means the control exists in code but no automated or live proof exists yet.

## 4. Dependencies

`npm audit --omit=dev --audit-level=high` exit 0 on the candidate (14 low/moderate remain: dompurify, fast-uri, ip-address, katex chain via streamdown/mermaid, sprintf-js via mammoth). Overrides pin `undici` 7.29.1 and `@modelcontextprotocol/sdk` 1.31.0; `sdk-compat.test.ts` guards the MCP SDK pin. The audit runs locally (`npm run check:audit`) and in CI with the same command.

## 5. Open items (not fixed in this release, each needs an owner decision)

- SEC-1C-01: consequential write tools execute in the same model turn without a second human step.
- SEC-1C-04: public incident beacon limiter fails **open** by Article 26(d) of the SADEED constitution — a policy choice, not a bug.
- SEC-1C-05: permissive CSP.
- SEC-1C-08 (design part): the email queue authenticates pg_cron with the service-role key.
- Unsubscribe GET acts as a token oracle (email suppression flow).
- 1D-02: public `/security`, `/trust`, `/dpa` pages assert RPO/RTO and backup guarantees with no evidence.
- RLS isolation never measured live; 27 tests blocked.
