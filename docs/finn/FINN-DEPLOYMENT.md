# دليل نشر FINN

## 1. ما قبل النشر

1. أنشئ نسخة قاعدة بيانات قابلة للاستعادة.
2. طبّق الترحيلات زمنيًا في بيئة مرحلية أولًا، ومنها ترحيل مجلس الوكلاء العشرة وأدوات RAG المحكومة.
3. راجع سياسات RLS والمنح؛ لا تستخدم `DROP ... CASCADE` لمعالجة اختلافات المخطط.
4. ضع مفاتيح Gemini وSupabase وElevenLabs والموصلات الاختيارية في خزنة أسرار الخادم.

## 2. سياسة النماذج

- الاستدلال والوكلاء والتحويل الصوتي: `gemini-3.6-flash` عبر المحول الرسمي لـGoogle.
- التضمينات: `gemini-embedding-2` بأبعاد 1536 المطابقة لفهرس المشروع.
- لا يقبل الخادم نموذجًا يرسله العميل، ولا يملك مسار تبديل إلى مزود ذكاء آخر.

## 3. بوابات الجودة

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run build
npm run check:performance
npm run check:secrets
```

## 4. اختبارات القبول

| الاختبار | النتيجة المطلوبة |
| --- | --- |
| سؤال ضمن الأمن الصناعي | جواب عربي واضح، متخصص، ومدعوم بالمراجع عند استخدام RAG |
| سؤال خارج النطاق | رفض موجز يعيد المستخدم إلى نطاق الأمن الصناعي |
| مهمة FINN عادية | القائد + الوكلاء العشرة موجودون في خطة المهمة |
| بحث RAG | نطاق مؤسسة صريح، بوابة الأدلة ناجحة، ومرجعان موثوقان على الأقل |
| فجوة معرفة | تسجل كفجوة؛ لا تتحول إجابة النموذج إلى حقيقة موثقة |
| محتوى مرشح | يبقى `verified=false` حتى اعتماد بشري مخوّل |
| سؤال صوتي | Gemini يحول الصوت، وElevenLabs ينطق الرد من دون كشف النص المخفي |
| أداة مؤثرة | تحقق صلاحية ومؤسسة وموافقة وسجل تدقيق |
| غياب المفتاح أو البيانات | فشل صريح وآمن من دون ادعاء نجاح أو بيانات حية |

## 5. التراجع

أوقف الإصدار الجديد واستعد النسخة أو نفّذ ترحيلًا عكسيًا مراجعًا يستهدف الكائنات المضافة فقط. لا تحذف معرفة أو سجلات تدقيق أو بيانات مستأجرين تلقائيًا.
