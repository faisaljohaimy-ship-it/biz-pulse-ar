# SADEED — Lovable independence assessment (2026-10-17)

Read-only inventory of every place where the running system depends on Lovable, with the honest state of each. Nothing here was changed or migrated; the point is to know what "removing Lovable" would actually touch. Removing the Lovable **editor** is not the same as removing Lovable **runtime** dependencies — most of the list below is runtime.

## 2. What the pause on 2026-10-16/17 proves

The backend pause (database, auth, storage stopped; `select now()` → 504 from 20:4x UTC on 10-16 through 03:02 UTC on 10-17; credits 0 / 3,625) is a **single point of failure in the Lovable Cloud layer**, not in the code: the worker kept serving static pages and the guest chat's local reply, while every stateful feature (sign-in, uploads, maintenance page, chat persistence and RAG, voice quota gates, cron, MCP OAuth) stopped. The repair candidate makes the application fail closed and cheaply in that state; it does not remove the dependency.

## 3. Evidence level of each statement

- Package list, imports, hosts and workflow files: read from the repository at `b81398e5c` (this branch).
- Lovable project facts: read-only `get_project` (published, synced to `72f21ccd1`) and `get_database_status` (Supabase enabled) on 2026-10-17 02:36 UTC; database probe 504 at 02:37 and 03:02 UTC.
- Not verified from here: Lovable Cloud backup/PITR configuration, the exact Cloud plan, whether the `rag-ingest` / `rag-retrieve` edge functions under `supabase/functions` are deployed, and the live `cron.job` table.

## 4. Recommendation

Keep the Supabase-compatible backend (its API surface is standard) but move its **ownership** out of Lovable Cloud only through the reversible, approval-gated plan in `docs/operations/SADEED_MIGRATION_RUNBOOK.md`. Make hosting independent first (lowest risk: `deploy.yml` already exists and the build output is already Cloudflare-shaped), then e-mail and OAuth, then the MCP wrapper, and Microsoft 365 last. The target state is described in `docs/architecture/SADEED_TARGET_ARCHITECTURE.md`.
