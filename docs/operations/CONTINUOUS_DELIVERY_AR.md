# التسليم المستمر المحكوم لسَدِيد

قرار المالك المكتوب في ٢٢ نوفمبر ٢٠٢٦ يجيز استمرار التطوير والدمج في `main` والنشر إلى Production بعد بوابات الجودة، وينسخ تقييد Preview السابق لهذه المهمة. لا يشمل التفويض إجراءات أمنية تشغيلية أو إرسال رسائل أو ترحيلات قاعدة الإنتاج أو تعديل RLS/DNS أو استدعاء ذكاء مدفوع في فحوص النشر.

## مسار الإصدار

يبقى `git.deploymentEnabled.main: false` في `vercel.json`. وظيفة `Deploy to Vercel` هي متحكم الإصدار الوحيد: اكتمال `CI Verification` بنجاح على حدث `push` إلى `main` في المستودع نفسه، ثم إثبات أن SHA الكامل ما زال رأس `main`. طلبات الدمج والفروع والمستودعات المنسوخة والتشغيلات القديمة لا تنشر الإنتاج. كل تشغيل يدوي للمتحكم، بما فيه Preview، مقصور على `refs/heads/main` قبل منح بيئة الأسرار؛ معاينات فروع الميزات تبقى عبر تكامل Vercel Git القائم.

وظيفة التنسيق السابقة لم تعد كاتبًا آليًا لـ`main`: `autoformat.yml` يعمل يدويًا من `main` بصلاحية قراءة فقط، ويصدر رقعة تنسيق للمراجعة دون commit أو push أو تعطيل CI. تطبيق الرقعة يمر بفرع ومراجعة وفحوص كأي تغيير؛ لذلك لا يستطيع المنسّق تحريك رأس الفرع بعد ختم الجودة.

تتسلسل النشرات في مجموعة واحدة دون إلغاء نشرة قائمة. يُلتقط خط التراجع من ارتباط **كل من** `neexios.com` و`www.neexios.com`، وتُثبت جاهزيته وبصمته عبر `/api/public/live`. يجب أن يكون الإصدار الجديد امتدادًا له؛ تُرفض المقارنة الناقصة أو التي تتضمن ٣٠٠ ملف فأكثر.

Vercel CLI مثبت على `64.5.0` وإجراءات GitHub مثبتة ببصماتها. يستخدم البناء المرحلي `--prod --skip-domain` مع SHA/ref صريحين لختم البناء. تُثبت READY وهوية المشروع والوجهة والبصمة، ثم يُقرأ `/api/public/live` بواسطة `vercel curl` المصادَق. يجب أن تبقى الدومينات على النسخة السابقة، وأن يظل `main` عند SHA نفسه قبل ترقية الأثر المرحلي نفسه.

قبل الترقية وبعدها تُقرأ صفحات `/auth` و`/sec/decision-center` و`/sec/incidents` وتُثبت استجابة HTML 200 وأصول JavaScript/CSS محلية صحيحة MIME وغير فارغة، مع رفض صفحات الأعطال. بعد الترقية تُثبت هذه الصفحات وعلاقة الدومينين وختم الحياة خلال ٩٠ ثانية من بدء الترقية. التراجع يفحص صفحات النسخة القديمة القائمة (`/auth` و`/sec/incidents`)؛ وجود ميزة المركز الجديدة ليس شرطًا لإثبات النسخة التي سبقتها. لا يستدعي المسار `/api/public/health` أو قاعدة أو مخزن حدود أو دردشة أو صوت. هذه فحوص HTTP؛ يبقى فحص المتصفح المروي للتفاعل والترجمة والتقرير خطوة قبول منفصلة. لا يدّعي فحص الحياة اختبار جاهزية القاعدة أو جودة إجابات الذكاء. غياب العينة أو اختلاف البصمة فشل.

الفشل قبل الترقية لا يشغّل تراجعًا. بعد محاولة الترقية فقط يُعاد الأثر السابق المثبت إن كانت الدومينات ما زالت تخص هذه النشرة أو خط أساسها. يُرفض التراجع الآلي إذا ظهر كاتب إنتاج آخر. نجاح التراجع يحتاج إلى إثبات الدومينين والبصمة؛ وإلا تظل النتيجة حمراء وموسومة `ROLLBACK UNVERIFIED`.

## مراجعة التغييرات الحساسة

ترحيلات Supabase وإعدادات النشر/التبعيات/البيئة وسكربتات الإصدار وأسـطح API وحراس المصادقة والصلاحيات والإنفاق والمزوّدين والرسائل ووحدات الخادم تتوقف قبل إنشاء نشرة آلية. تؤخذ المسارات القديمة والجديدة للملفات المعاد تسميتها معًا. لا يكفي CI لإجازة هذه الفروق.

يستطيع المالك تشغيل `workflow_dispatch` من `main` بمدخلات `target=production` و`confirm=deploy` و`owner_review_sha` المطابق كاملًا، مع `owner_review_context` كرابط PR أو issue في المستودع يسجل المراجعة. يجب أن يكون المرسل مالك المستودع؛ ويظل نجاح CI على push لنفس SHA مطلوبًا. هذا يثبت مراجعة الإصدار، ولا يصرح بتشغيل الترحيلات أو الإجراءات نفسها. المعاينة اليدوية من `main` تبقى متاحة بـ`target=preview` دون ترقية الإنتاج. حماية الفرع وبيئة GitHub وحماية Vercel تبقى نافذة.

## المتطلبات والحالة المقيسة

أسماء إعدادات GitHub المطلوبة: السر `VERCEL_TOKEN` والمتغيران `VERCEL_ORG_ID` و`VERCEL_PROJECT_ID` (يمكن توفير المعرفين كسرّين). لا تُطبع القيم ولا يمر الرمز في معاملات العمليات. نقص الرمز أو اختلاف المعرفين عن المشروع والفريق المعتمدين يوقف الإصدار قبل أي نشر. `vercel curl` يستعمل المصادقة القائمة ولا يعطل حماية النشرة.

المشروع `prj_9ijbW2tJ2J5p2C2RwbK4A6qJfIpO`، والفريق `team_lFSyX3zRr4VzdY5egj5xO2Ro`. قراءة أسماء أسرار ومتغيرات GitHub أعادت HTTP 403؛ توافرها **غير مثبت**، ولا يُفترض أن التشغيل الآلي مفعّل فعليًا بمجرد دمج الملف. لا تُطلب مفاتيح من المستخدم في المحادثة.

ميزانية الدورة شرط مستقل لا قيمة افتراضية له: يجب أن يضبط المالك `SADEED_DEPLOY_CYCLE_BUDGET` كعدد صحيح محدود و`SADEED_DEPLOY_CYCLE_STARTED_AT` كتاريخ UTC كامل بصيغة `2026-11-22T00:00:00.000Z` يحدد بداية الدورة الفعلية؛ التاريخ هنا مثال صيغة لا إعداد تلقائي. يعاد استخدام `checkBudget` و`EMERGENCY_RESERVE` من `src/lib/rag/deployment.ts` عبر وضع TypeScript الصريح في Node، دون نسخ محرك الحكم. تُعد كل نشرات المشروع منذ الحد المحدد بجميع حالاتها، بما فيها المعاينات الأصلية والفاشلة. تُرفض الأدلة المكررة أو الناقصة أو ذات الصفحات المتبقية والتواريخ غير الصالحة. العمل العادي يحتاج إلى أكثر من نشرتين متبقيتين قبل إنشاء نشر، ويثبت عدًّا جديدًا بعد البناء ويحفظ الاحتياطي. تُسجل البصمة والوجهة والنتيجة والمتبقي؛ يبقى الفشل أحمر ولو نجح تراجعه. معاينات Git الأصلية لا تمر بهذا المتحكم لكنها تُحسب في ميزانيته؛ لا يدّعي المتحكم ضبط جميع كتّاب Vercel خارج نطاقه. غياب إعدادات الدورة أو دليل العد يوقف الإنشاء. التشغيل الدائم **غير مثبت التفعيل** حتى تثبت الميزانية والأسرار معًا.

دورة الإطلاق الحالية بدأت `2026-11-22T21:56:15.241Z`. عُدّل حدها مرة من ٤ إلى ٥ محاولات لتغطية معاينة إضافية ضرورية لإزالة كاتب التنسيق غير المفحوص: معاينتان + نشر إنتاج واحد + نشرتا طوارئ. لم يتغير تاريخ البدء ولم يُصفّر العد؛ المعاينة الأولى مستهلكة، وجميع الحالات تُحسب عند كل قرار. هذا حد لهذه الدورة وحدها، وليس إعدادًا دائمًا أو تغييرًا لميزانيات JavaScript/CSS.

خط أساس الإنتاج المقيس في ٢٢ نوفمبر ٢٠٢٦: `dpl_87SSgBf9CMcoJKLAh8JJRemABzSh` عند SHA `a384a548c498dbec3a244aef723ea97f28bf5a4c` والدومينان يشيران إليه. يُعاد التقاط الخط لكل إصدار؛ هذه ليست قيمة تراجع ثابتة. كان `main` متقدمًا عليه بـ٦٢ التزامًا/٣٤ ملفًا. روجعت فروق التشغيل ونجحت ١٥ حزمة انحدار/١٥٥ اختبارًا دون شبكة أو ذكاء مدفوع. السجل المحلي `/tmp/sadeed-prod-main-delta-regressions.log` ليس أثرًا محفوظًا في المستودع.

للإطلاق الأول عند غياب أسرار GitHub يمكن استخدام اتصال Vercel القائم بعد البوابات نفسها وبقرار المالك المسجل: إثبات تعطيل الإسناد التلقائي للدومينات (`autoAssignCustomDomains:false`؛ أداة إنشاء النشرة لا تعرض `skip-domain`)، إنشاء Production من SHA الدمج الدقيق، فحص الأثر قبل الترقية، ثم ترقية الأثر نفسه وإثبات الدومينين. لا يُنشأ نشر يغيّر حركة الإنتاج قبل الفحص. لا تُستعاد قاعدة Lovable المجمدة ولا تُستخدم أمثلة force-push القديمة.

## الدليل القابل لإعادة التشغيل

`node --experimental-strip-types --test scripts/cd-gate.regression.test.mjs` ينفّذ برنامج workflow نفسه بمزودات وهمية. يغطي إصدارًا صالحًا، وفشل CI وSHA قديمًا ومستودعًا منسوخًا وإعدادات ناقصة/خاطئة ومراجعة حساسة خاطئة وإعادة تسمية حساسة وختم مرحلة خاطئ وتغير main بعد البناء وفشل الترقية والتراجع وكاتبًا متزامنًا. كما يغطي حد الاحتياطي وميزانية ناقصة/NaN وتاريخًا خاطئًا وعدًّا مكررًا/ناقصًا. فحوص الحياة تستخدم GET `/api/public/live` وحده. هذه اختبارات دون نشر حي؛ تسجل خلاصة GitHub الفعلية البصمات والمعرفات والوجهات ونتيجة التحقق والتراجع.
