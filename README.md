# سَدِيد | SADEED

منصة إنجاز أعمال ثنائية اللغة، تتضمن مركز قيادة تفاعليًا، سَدِيد، طبقة
صلاحيات متعددة المستأجرين، وتكاملات مؤسسية قابلة للتهيئة.

يدعم سَدِيد المحادثة الصوتية بصوته الموحّد، الأسئلة النصية، تحليل الصور
والفيديو والصوت والمستندات، وإرسال البريد وSMS عبر مزوّدات مؤسسية تُضبط من
متغيّرات البيئة. الإرسال الخارجي محصور بلحسابات الإدارية المصرّح لها، ويمر
دائماً عبر معاينة كاملة وإقرار بشري ورمز اعتماد قصير الصلاحية قبل إرسال وحيد،
ثم تُحدّث حالة التسليم عبر Webhook موقّع.

يمكن للزائر مشاهدة العرض التنفيذي كاملاً دون اسم مستخدم أو كلمة مرور. لا تظهر
حقول الدخول إلا بعد إقرار صريح بالانتقال من العرض المفتوح إلى مرحلة التفعيل؛
ولا يمنح هذا الإقرار أي صلاحية داخل النظام.

يبدأ صوت سَدِيد بعد ضغط المستخدم دائماً، ويعرض حالة التحضير والتشغيل والخطأ
بوضوح، ولا يُستبدل بصوت متصفح آلي عند غياب إعداد ElevenLabs. (المسار
`/executive-bridge` «جسر القيادة» حُذف من النظام كليًّا بقرار المالك
٢٠٢٦/٠٨/٠٥، ولا بديل مسجَّل له.)

## مسار إجابة سَدِيد — سلوك متحقق في الكود

- لوحة `SadeedCopilot` ترسل النص والمرفقات عبر `SadeedProvider` و`sadeedAuthedFetch` إلى `/api/chat`؛ أوامر الصفحات تمر عبر `sadeedBrain`. اللوحة نفسها تستعمل `chat.sendMessage`، فلا يُدّعى مرور كل طلب عبر الدماغ.
- المزوّد الأساسي Google Gemini (`gemini-3.6-flash`). البديل القائم Gemini عبر Lovable AI Gateway (`google/gemini-3-flash-preview`) عند تهيئة `LOVABLE_API_KEY` وفشل مؤقت أو عدم دعم النموذج الأساسي. ليس اتصالًا مباشرًا بـOpenAI.
- حد العميل 30 ثانية حتى استلام الاستجابة، وبحث الجلسة محدود بخمس ثوانٍ؛ زر الإيقاف يقطع الانتظار فورًا. هذا لا يثبت أن النموذج يجيب خلال 30 ثانية ولا يحد زمن قراءة جسم البث بعد استلامه.
- الخادم يجمع الإجابة ويفحصها قبل بث النص الآمن؛ لا يعرض الرموز الخام أثناء توليد النموذج. لا تتغير حدود التكلفة أو سياسة البوابة المغلقة عند تعذر مخزن المعدّل.
- رفض المزوّد الصريح (400/401/402/403) لا يفعّل البديل. إعادة الطلب بلا جلسة عند 401/403 تخص رفض جلسة التطبيق، لا رفض مزوّد الذكاء.
- `/api/chat/health` يعيد حالة المخزن في `gate` وحضور المفتاح؛ `ok` يؤكد نجاح الفحص، لا نجاح توليد إجابة فعلية. `pingChat` ينقل هذه الحالة.
- سجل اللوحة يحتفظ بسياق الجلسة في الذاكرة ويرسل آخر 20 رسالة. كتابة `threads/messages` تتطلب مستخدمًا متحققًا و`threadId`؛ الناقل الحالي يرسل `id` فقط، لذا لا يُدّعى حفظ محادثة اللوحة كاملة بين الزيارات. الكتابات الخلفية قد تفشل وتُسجّل دون تعطيل الرد.

## OpenAI المباشر — إضافي وغير افتراضي

`src/lib/sadeed/openai-provider.server.ts` يستخدم حزمة `@ai-sdk/openai` الرسمية وResponses API
بالنموذج `gpt-4.1-mini` ومفتاح `OPENAI_API_KEY` من Secrets على الخادم فقط.
طلب `POST /api/chat` مع `X-SADEED-Provider: openai` يختار هذا المسار؛ اللوحة تبقى على Gemini
حتى ينجح التحقق الفعلي. لا Edge Function منفصلة ولا مساعد مكرر ولا تغيير قاعدة أو صلاحيات.
تبقى بوابات المعدّل والحصة اليومية والتزامن الحالية؛ OpenAI محدود بـ1200 رمز خرج لكل خطوة،
خطوتين كحد أقصى، مهلة توليد 25 ثانية، ودون إعادة محاولة أو تحويل تلقائي لمزوّد آخر.
`store: false` يمنع حفظ الاستجابة في سجل Responses، ولا يَعِد بسياسة احتفاظ أخرى.
الترويسة `X-SADEED-Generation` تميّز نجاح التوليد عن رد الخطأ الآمن حتى مع HTTP 200.

تجربة 2026-10-19 عبر `/api/chat`: وصل الطلب إلى OpenAI ورُفض بـ429؛ الفحص المباشر
أكد `insufficient_quota` / `credit_balance_exhausted`. لم يصل رد مولّد ناجح؛ يلزم معالجة
رصيد OpenAI ثم إعادة التحقق قبل تفعيل المسار في اللوحة. لم يُنشر هذا التغيير.

## متطلبات التشغيل

- Node.js 22 أو 24
- npm 10 أو أحدث
- قاعدة البيانات والمصادقة وStorage الحالية في Lovable Cloud عند تشغيل الوظائف الحية؛ إعدادات النسخة المستقلة تُقدّم من بيئة الخادم والبناء.

## العمارة الحالية وحدود التحقق

- التطبيق React 19 وTanStack Start، وليس تطبيقًا منفصلًا عن الخادم. `src/routes/__root.tsx` يركّب `SadeedProvider` و`SadeedCopilot` مرة واحدة؛ صفحات `/sadeed` و`/assistant/` و`/assistant/$threadId` تستعمل `CanonicalSadeedRoute` لفتح اللوحة نفسها.
- نقطة الدردشة الفعلية `src/routes/api/chat.ts` (`POST /api/chat`) هي مسار خادم TanStack؛ ليست Supabase Edge Function. `src/server.ts` يغلّف مدخل الخادم، والبناء يستهدف Cloudflare Workers افتراضيًا. لا يثبت ذلك أن النسخة الحالية منشورة.
- `src/lib/ai-gateway.server.ts` ينشئ Google Gemini مباشرة. `src/lib/sadeed/backup-provider.server.ts` يستعمل محوّل OpenAI-compatible للوصول إلى نموذج Gemini في بوابة Lovable؛ اسم المحوّل لا يعني استخدام نموذج OpenAI. مسار OpenAI الإضافي أعلاه يستعمل اتصالًا مباشرًا مستقلًا؛ الافتراضي يبقى Gemini.
- الخادم يتحقق من جلسة المستدعي ثم عضويته في `org_members`. القراءات والكتابات العادية تستعمل عميل المستدعي وسياسات الوصول؛ الضيف لا يحصل على أدوات المؤسسة أو استرجاعها أو حفظ المحادثة. هذا وصف للكود، وليس شهادة جديدة على سياسات قاعدة الإنتاج.
- `src/start.ts` يضيف حامل الجلسة إلى استدعاءات `createServerFn`. ناقل الدردشة يضيفه بنفسه؛ انتهاء مهلة التحقق لا يمنح صلاحيات مستخدم متحقق.
- `src/lib/sadeed-core/services/chat-error-text.ts` يحوّل أخطاء العميل إلى رسائل عربية آمنة. خطأ المزوّد يُحوّل في الخادم إلى رد آمن؛ قد يصل HTTP 200 مع سطر خطأ، فلا يكفي نجاح HTTP لإثبات نجاح النموذج.
- سياق اللوحة وحالتها في `src/lib/sadeed-core/providers/sadeed-provider.tsx` و`state/sadeed-store.ts`؛ الرسم يستعمل `react-markdown` و`remark-gfm` في `SadeedCopilot.tsx`.

### أسماء إعدادات البيئة — دون قيم

| النطاق                           | الأسماء                                                                                                               | الاستخدام                                                                  |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| البناء/المتصفح، إعدادات عامة فقط | `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`                                      | ربط العميل بالخدمات الحالية؛ ليست مفاتيح إدارية                            |
| الخادم                           | `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`                                               | ربط الخادم ومخزن بوابات المعدّل؛ المفتاح الإداري لا يدخل المتصفح           |
| الذكاء الأساسي                   | `GEMINI_API_KEY` أو `GOOGLE_GENERATIVE_AI_API_KEY`, `GEMINI_MODEL`                                                    | المفتاح الأساسي مطلوب لتجاوز الرد المحلي؛ النموذج محصور بقائمة الخادم      |
| البديل الاختياري                 | `LOVABLE_API_KEY`                                                                                                     | نموذج Gemini عبر البوابة؛ لا يكفي وحده لتجاوز شرط المفتاح الأساسي الحالي   |
| الصوت الاختياري                  | `ELEVENLABS_API_KEY`                                                                                                  | صوت سَدِيد عبر الخادم فقط                                                  |
| بوابات التكلفة                   | `SADEED_CHAT_MAX_INFLIGHT`, `SADEED_CHAT_DAILY_PER_IDENTITY`, `SADEED_CHAT_DAILY_GLOBAL`, `SADEED_GATE_DEGRADED_MODE` | سقوف التزامن واليوم؛ الوضع `bounded` قرار فوترة للمالك، لا يُفعّل تلقائيًا |
| النشر المستقل الاختياري          | `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`                                                                       | صلاحيات النشر في حساب المالك، لا إعدادات المتصفح                           |

مسار Gemini الافتراضي لا يتطلب `OPENAI_API_KEY`؛ مسار OpenAI الإضافي يتطلبه. وجود أسماء في وثيقة أو `.env.example` لا يثبت تفعيل خدمة. المفاتيح الخاصة تُضبط في بيئة الخادم فقط، ولا تُنسخ إلى README أو Git أو أي متغير `VITE_*`. لا يُفترض أن كل اسم في `.env.example` يستعمله المسار الحالي.

## التشغيل المحلي

```bash
cp .env.example .env.local
npm ci
npm run dev
```

املأ فقط القيم المطلوبة في `.env.local`. لا تُودع مفاتيح الإنتاج أو
`SUPABASE_SERVICE_ROLE_KEY` في المستودع.

لمعاينة حزمة Cloudflare بعد بنائها، شغّل `npm run build` ثم
`npm run preview`. يستخدم أمر المعاينة إعداد Worker الناتج نفسه بدل خادم Vite
العام.

## بوابة الإصدار

```bash
npm run check
npm run lint
npm run typecheck
npm test
npm run build
npm run check:secrets
npm run check:audit
```

تجمع `npm run check` بين ESLint، فحص TypeScript، اختبارات Vitest، وبناء
الإنتاج، وفحوص الأداء والتباين والأسرار وتدقيق الاعتمادات. الأوامر المنفردة أعلاه بدائل للتشخيص وليست إثباتًا على تنفيذ البوابة كاملة. اختبارات E2E التي تعتمد على خدمات المصادقة تُشغّل عبر `npm run test:e2e`
بعد توفير بيانات بيئة الاختبار.

فحص توثيق ٢٠٢٦/١٠/١٩: شُغّل `bunx vitest run src/lib/sadeed-core/services src/lib/sadeed/backup-provider.model-404.test.ts src/lib/sadeed/backup-provider.retry-after.test.ts src/routes/api/chat-health.test.ts`؛ نجح 47 اختبارًا في 10 ملفات. لم تُشغّل بوابة `npm run check` كاملة في هذا الفحص، ولم يُختبر اتصال OpenAI أو توليد البديل فعليًا.

## النشر

خط Lovable هو الناشر الأساسي الحالي بحسب `.github/workflows/deploy.yml`؛ Cloudflare Workers هدف البناء الافتراضي، ونشر GitHub Actions مسار احتياطي اختياري. `ci.yml` يستدعيه بعد بواباته على دفع `main`؛ إن غابت إعداداته يتخطى النشر مع تحذير، فالأخضر لا يثبت نشرًا. اختبار الأمان E2E استشاري عند غياب بياناته، ولا يُدّعى أنه بوابة إلزامية في كل تشغيل.

خطوات إطلاق آمن **عند إذن المالك، لا في فحص التوثيق هذا**:

1. تحقق من المستودع المتصل والفرع وحالة المزامنة وتحذير النسخة المحفوظة في **Project settings → Git**. معلومات الدستور عن اسم المستودع ليست تحققًا من اتصال المنصة؛ لا تُستعد نسخة ولا تُكتب فروع فوق بعضها لحل الشك.
2. شغّل بوابة الاختبارات والبناء على النسخة المقصودة. `npm run build` يكتب معرّف البناء ويُخرج `.output/server/wrangler.json`؛ `npm run preview` يعاين هذه الحزمة محليًا.
3. أكد إعدادات الخادم والبناء لدى الوجهة. لا تطبق كل ملفات الترحيل تلقائيًا؛ أي تغيير قاعدة إنتاج ينتظر إذن المالك والتحقق من المخطط الفعلي والنسخة القابلة للاستعادة.
4. انشر من Lovable عند الإذن، أو استعمل المسار الاحتياطي المهيأ والمتحقق من بواباته. لا تفعل المسارين على الوجهة نفسها بلا قرار واضح. وجود `vercel.json` وفرع إعداد Vercel لا يثبت اعتماده للإنتاج.
5. تحقق من معرّف النسخة المنشورة و`/api/public/health` و`/api/chat/health`، ثم تسجيل الدخول والصلاحيات وسؤال عربي حقيقي والتكاملات المعنية. المزامنة ليست نشرًا، وفحص حضور المفاتيح ليس فحص توليد.

راجع [DEPLOYMENT.md](DEPLOYMENT.md) كمرجع تاريخي، مع تقديم الشروط الفعلية في `ci.yml` و`deploy.yml` وقرارات المالك على العبارات القديمة المخالفة. هذا الفحص لم يغيّر النشر أو الأسرار أو قاعدة البيانات.
